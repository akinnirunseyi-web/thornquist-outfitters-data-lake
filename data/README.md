## Schema reconciliation candidates (for Justin to implement)

- POS `receipt_id` vs ecommerce `orderId`
- POS `sale_date` vs ecommerce `orderTimestamp` (date vs ISO timestamp)
- POS `customer_id` vs ecommerce `customerRef`
- POS `product_category` title case vs ecommerce `items[].category` lower case
- POS line-item `quantity` / `unit_price_cad` vs ecommerce nested `items[].qty` / `priceCAD`

## Deliberately invalid records — DO NOT clean source files

- POS duplicate `receipt_id` (`POS0010`); invalid `sale_date` on `POS0016`; orphan customer ID on `POS0024`; negative quantity on `POS0032`; placeholder category on `POS0040`.
- Ecommerce duplicate `orderId` (`WEB0006`); malformed `orderTimestamp` on `WEB0013`; orphan customer on `WEB0021`; negative price on `WEB0029`; placeholder category on `WEB0037`.

These examples support completeness/validity, uniqueness, referential-integrity, and range checks. Justin must decide and implement the actual rules, quarantine, and promotion logic.
